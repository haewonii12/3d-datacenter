# 업로드 파일 형식 안내

두 가지 형식을 지원합니다. 어느 쪽이든 `데이터 ▾ → 파일 불러오기…` 또는 화면에 끌어다 놓으면 됩니다.

| 형식 | 예시 파일 | 언제 |
|---|---|---|
| **CSV (Excel)** | [`upload-example.csv`](upload-example.csv) | 엑셀로 관리하는 경우. 한 행 = 서버 한 대 |
| JSON | [`upload-example.json`](upload-example.json) | 프로그램으로 만드는 경우 |

두 예시 파일은 같은 데이터입니다. 화면에서 `CSV 내보내기` / `JSON 내보내기`로 받은 파일도 그대로 다시 올릴 수 있으니, 현재 데이터를 내보내서 양식으로 써도 됩니다.

## CSV (Excel)

엑셀에서 `upload-example.csv`를 열어 행을 고치고 **CSV로 저장**하면 됩니다. `CSV UTF-8`과 그냥 `CSV (쉼표로 분리)`(한글 CP949) 둘 다 읽습니다. 구분자는 쉼표·세미콜론·탭 모두 됩니다. `.xlsx`는 직접 읽지 않으니 CSV로 저장해 주세요.

**한 행 = 서버 한 대**입니다. 데이터센터·층·랙 정보는 서버마다 반복해 적습니다(같은 값이면 첫 행에만 있어도 됨).

| 열 | 필수 | 설명 |
|---|---|---|
| `dc_id` | ✔ | 데이터센터 ID |
| `dc_name` | | 데이터센터 이름 (없으면 ID) |
| `floor_id` | ✔ | 층 ID (예: `1F`, `B1`) |
| `floor_level` | | 아래→위 순서 정수 |
| `floor_rows`, `floor_cols` | | 층 그리드 크기. 비우면 그 층 랙의 최대 row/col |
| `rack_id` | | 비우면 `R-{층}-{row}-{col}` |
| `rack_row`, `rack_col` | 서버 행이면 ✔ | 랙 위치 (1부터) |
| `total_u` | | 기본 42 |
| `server_id` | | 비우면 `hostname`을 ID로 씀 |
| `hostname` | `server_id`가 없으면 ✔ | |
| `ip` | | |
| `unit` | 서버 행이면 ✔ | 서버 맨 아래 U |
| `height_u` | | 기본 1 |
| `services` | | `이름|팀|상태; 이름|팀|상태` — 팀·상태는 생략 가능, 상태는 `ok/warn/down` 또는 `정상/경고/중단` |

- 열 순서는 자유이고, 모르는 열(예: `비고`)은 무시합니다. 한글 열 이름도 됩니다: `데이터센터ID`, `데이터센터`, `층`, `레벨`, `랙ID`, `랙Row`, `랙Col`, `서버ID`, `호스트명`, `시작U`, `높이U`, `서비스` 등 (띄어쓰기·대소문자 무시).
- **빈 랙**: 서버 열을 비운 행 (랙 열만 채움). **빈 층**: 랙·서버 열을 비운 행.
- 같은 층/랙의 값(`floor_rows`, `rack_row` 등)이 행마다 다르면 오류입니다.
- 오류는 **엑셀 행 번호**로 표시됩니다 (예: `5행 unit · 정수가 아닙니다: "abc"`). 오류가 있으면 파일 전체가 거부되고 기존 데이터는 그대로입니다.

예시 (`upload-example.csv` 일부):

```csv
dc_id,dc_name,floor_id,floor_level,floor_rows,floor_cols,rack_id,rack_row,rack_col,total_u,server_id,hostname,ip,unit,height_u,services
seoul-1,서울 DC1,1F,1,2,4,R-1F-01-01,1,1,42,srv-00001,web-sel-001,10.11.1.1,1,2,"nginx|웹플랫폼|ok; node-exporter|SRE|ok"
seoul-1,서울 DC1,1F,1,2,4,R-1F-02-04,2,4,42,,,,,,
```

## JSON

실데이터를 프로그램으로 만들 때는 `upload-example.json`과 같은 구조로 만들면 됩니다. 인코딩은 UTF-8, 확장자는 `.json`.

### 구조

```
datacenters[]            데이터센터 (1개 이상)
└─ floors[]              층 (데이터센터마다 1개 이상)
   └─ racks[]            랙 — 층 그리드의 (row, col) 칸에 놓임
      └─ servers[]       서버 — 랙 안의 시작 U(unit)와 높이(height_u)
         └─ services[]   서버에서 돌아가는 서비스
```

### 필드

| 위치 | 필드 | 필수 | 설명 |
|---|---|---|---|
| 루트 | `version` | | `2` |
| 데이터센터 | `id` | ✔ | 파일 전체에서 유일 (예: `seoul-1`) |
| | `name` | 권장 | 화면 표시 이름 (없으면 `id`) |
| 층 | `id` | ✔ | 데이터센터 안에서 유일 (예: `1F`, `B1`) |
| | `level` | | 아래→위 쌓는 순서 (정수, 지하는 0·음수). 없으면 배열 순서 |
| | `rows`, `cols` | ✔ | 층의 랙 자리 그리드 크기 (양의 정수) |
| 랙 | `id` | ✔ | 데이터센터 안에서 유일 |
| | `row`, `col` | ✔ | 1부터 시작, `rows`/`cols` 이내. 한 칸에 랙 하나 |
| | `total_u` | | 기본 42 |
| 서버 | `id` | ✔ | 데이터센터 안에서 유일 |
| | `unit` | ✔ | 서버 **맨 아래** U 번호 (1 = 랙 바닥) |
| | `height_u` | | 차지하는 U 수, 기본 1. 예: `unit 10, height_u 4` → U10–13 |
| | `hostname` | 권장 | 화면 표시·검색 대상 (없으면 `id`) |
| | `ip` | | |
| 서비스 | `name` | ✔ | 검색 대상 |
| | `team` | | 담당팀 |
| | `status` | | `ok`(정상) / `warn`(경고) / `down`(중단). 그 외·누락은 알수없음 |

## 자주 하는 실수 (공통)

- **ID는 같은 데이터센터 안에서만 겹치지 않으면 됩니다.** 서울과 부산 모두 `1F`, `R-1F-01-01`, `srv-00001`을 써도 됩니다 (예시 파일이 그렇게 되어 있음).
- 같은 랙에서 서버 U 범위가 겹치거나 42U를 넘으면 불러오기는 되지만 빨간 테두리와 ⚠ 경고가 표시됩니다.
- 그리드 밖이거나 이미 랙이 있는 칸의 랙은 경고와 함께 빠집니다.
- 필수 필드(✔)가 빠지거나 ID가 중복되면 파일 전체가 거부되고, 문제 위치가 `datacenters[0].floors[1].racks[4].id`처럼 표시됩니다. 기존 데이터는 그대로 남습니다.
- JSON에서는 `rack_id` 같은 평면 참조가 필요 없습니다. 서버를 랙 안의 `servers` 배열에 넣으면 됩니다.
- 화면의 `R01-C02`, `1F-R01-C01-U10–13` 같은 표기는 row/col/unit으로 자동 계산되므로 따로 넣지 않습니다.

## 예시 파일 내용 (두 파일 동일)

| 데이터센터 | 층 | 랙 | 서버 |
|---|---|---|---|
| 서울 DC1 (`seoul-1`) | 1F (2×4), 2F (2×4) | 4 (그중 1개는 빈 랙) | 5 — 1U·2U·4U, `height_u` 생략 1대, 서비스 0~2개, 상태 ok/warn/down |
| 부산 DC2 (`busan-1`) | 1F (1×3) | 1 | 1 |

화면에서 수정한 뒤 `데이터 ▾ → JSON 내보내기`로 받은 파일도 같은 형식이라 다시 업로드할 수 있습니다.
